I've built the tool under a working name, **qdvc-git-braid**. It's one Python file, `git-braid`, using only the standard library. You run it like this:

```
./git-braid mac=../MyApp-mac gtk4=../MyApp-gtk4 -o ../MyApp
```

It creates a new repo in which `mac/` and `gtk4/` each have their full history, with the commits from both repos interleaved by date. Authors, dates, time zones and messages are kept exactly. Because each file has been in its folder from its first commit, `git log -- mac/Foo.swift` and `git blame` work normally. Your source repos are never modified.

All 36 tests pass. A larger test with about 4,000 commits and 218 merges took about 2 seconds, and `git fsck --strict` found no problems. I've only tested on Linux (Git 2.43, Python 3.13). I checked that the code is valid Python 3.8, which is what Xcode's `python3` is, but I haven't run it on macOS or Windows.

### Choices I made that you may want to change

- **Ordering** uses the commit (committer) date by default, because that reflects when a commit actually landed, even after a rebase. `--order-by author` switches to the authored date. Each repo's own commit order is never changed, even if its dates go backwards.
- **Merges inside each repo are kept.** A commit on a merged side branch keeps the other platform's folder as it was where the branch started, so it only changes its own folder. `--linear` flattens each repo to its main line instead.
- **Tags** get the folder name in front (`v1.0` becomes `mac/v1.0`). GPG/SSH signatures on commits and tags are removed, because they'd no longer be valid.
- **Only one branch per repo** is imported: whichever is checked out, unless you say otherwise. Tags pointing at other branches are skipped, and the tool tells you how many.

### Extras I added that you didn't ask for

- **More than two repos and nested folders**, e.g. `apps/mac=… apps/gtk4=… shared=…`. Sources can also be URLs.
- **`--dry-run`** prints the planned order without creating anything.
- **A commit map** (a table of old and new commit IDs) for updating links in issues and PRs. `--trailer` also writes each commit's old ID into its message.
- **`--subject-prefix '[{folder}] '`** so that `git log --oneline` shows which platform each commit belongs to.
- **Checks at the end:** each folder must match its source's latest version, and every source commit must have been written.
- **Safety checks:** it refuses folder names that would clash on macOS or Windows, where filenames ignore case (`Mac` vs `mac`). It refuses incomplete clones (shallow or partial) and SHA-1/SHA-256 mixes. It won't write into a folder that isn't empty.
- **Warnings for files that only work at the repo root:** submodules, `.github/` workflows, other CI configs, `.mailmap`. It also warns about Git LFS, whose contents aren't copied, and about repos where one started as a copy of the other.
- If the script's folder is on your `PATH`, it also works as `git braid`.
